# Social Product Card 2.0 — approved design decisions

Owner approved all requirements and proposed limits on 2026-10-15. These decisions
describe intended implementation, not currently available API/schema. Existing
contracts remain authoritative until generated artifacts are updated with code.

## ADR-A/B: Authoring and identity

One Catalog Item has one optional social caption. Add nullable `social_caption` in
the next available forward-only migration; do not create independent posts or copy
description/price/stock into another source of truth. Keep item @Version/If-Match.

Caption maximum is 3,000 UTF-16 code units, matching Java/JS length. PostgreSQL
char_length counts Unicode code points differently; do not describe a
char_length<=3000 constraint as enforcing the identical UTF-16 boundary. Enforce
the approved application boundary and test supplementary Unicode explicitly.
Preserve inner newlines, trim edges and render plain escaped text.

New caption PATCH semantics: absent leaves current value; supplied null or empty/
whitespace clears it; supplied nonblank text replaces it. Add explicit presence
tracking for that field. Keep existing description and other patch semantics.
Changing caption/media of an approved item must re-evaluate the configured
moderation policy before public exposure, inside the versioned transaction.

## ADR-C: Preview and public contracts

Add `GET /api/v1/catalog/social-previews?itemIds=...` with 1–40 IDs and stable
deduplication. Return a map keyed by item ID with optional caption and up to six
ordered READY authorized media previews. Filter item and merchant exactly as the
existing social service. Do not fetch item detail per card or send this payload in
Catalog mode. Like/save viewer flags stay in existing viewer-specific summary.

No raw storageKey/upload URL/PII field is added. Reuse approved media URL contracts;
do not claim storage-object privacy merely because an item route is hidden.

## ADR-D: Admin and moderation

Add guarded read-only list/detail `/api/v1/admin/catalog-items[/{itemId}]`.
Use `AdminPageResponse` shape (`items,total,page,size`), default page 0/size 20,
maximum size 100 from existing AdminPageRequestValidator. Validate offset bounds,
q length and allowlisted CREATED_ASC/CREATED_DESC/UPDATED_DESC; default UPDATED_DESC.
Filters use existing item type, listingKind, listing/moderation status and merchant
ID. Resale is PRODUCT + RESALE; do not add new domain status/type enums.

Admin list/detail may read hidden/deleted items according to Admin privilege; this
does not change public visibility. Exclude seller/user PII and storage credentials.
Gather covers/media/cases in bounded queries, not one lookup per result. Caption/
video indicators are introduced only when their real schema exists, not fabricated.

Actions link the existing case pipeline. No direct item-status mutations. If an
item has no valid case, expose that fact; implement any new audited/idempotent
case-opening command separately rather than using a buyer report as an Admin hack.

## ADR-E: Gallery and video

Reuse catalog_item_media order/primary associations for images. Total maximum ten
media for new V2 authoring; first ordered image is cover. Preserve existing items
and their data: check legacy galleries before enforcing edit limits; do not silently
truncate them or force unrelated edits to drop existing media.

Video: at most one/item, at most 50 MiB; CATALOG_VIDEO and mixed-media constraints
need explicit support. Video flag defaults OFF. Duration target 60 s becomes an
enforced limit only after trustworthy metadata probing is implemented and tested.
Poster/codec/transcoding/cleanup/moderation/storage cost and browser acceptance
remain activation gates, not claims fulfilled by owner approval of the plan.

## ADR-F: Activity semantics

`GET /api/v1/me/social/activity?type=LIKED|SAVED|COMMENTED&limit=20&cursor=...`.
Default 20, max 50, min 1. Actor comes from the existing validated session, never
from request userId. Return current reaction state and individual ACTIVE author
comments on visible items, not an event audit history. Unlike/unsave/delete removes
the corresponding row from the projection.

Use descending timestamp + deterministic unique tie-breaker. Opaque cursor is
bound to actor and activity type using the project's established cursor patterns;
reject misuse/malformed inputs. Response private/no-store. Existing V018 indexes
are evaluated before adding indexes; measure actual plans on disposable data.

## Flags and release

Separate default-OFF gates for Admin reads/UI, caption authoring, preview/gallery,
activity and catalog video. Backend enforcement accompanies FE hiding; direct API
access cannot enable a disabled write. Old Catalog/Social APIs remain functional
when V2 flags are OFF. Local test properties can enable one feature in isolation.

Owner approval permits local implementation; it does not supply missing staging.
Keep release blocked until required Phase 4/V2 real E2E, responsive, security/load,
backup/restore/rollback and immutable image evidence exist. No automatic deployment.
