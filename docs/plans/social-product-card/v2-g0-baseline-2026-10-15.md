## Route and schema map

- Preserve existing catalog social summary, item comments, me likes/saves/comments,
  reports and moderation-case commands unchanged.
- Preserve merchant catalog POST/PATCH and If-Match; add optional caption to their
  payloads later. Existing PATCH null means unchanged for current description; a
  new caption requires explicit presence semantics without changing description.
- Proposed V2 routes remain absent in both source/OpenAPI:
  `/api/v1/admin/catalog-items[/{itemId}]`, `/api/v1/catalog/social-previews`,
  `/api/v1/me/social/activity`.
- Domain types are PRODUCT/SERVICE; RESALE is `ListingKind`, not an item type.
  Domain listing statuses are DRAFT/ACTIVE/PAUSED/DELETED, not ARCHIVED. Preserve
  these enums and render/filter resale through listingKind.
- Item `@Version` and media composite PK already exist. Media association ordering
  is `sort_order` with `is_primary`; do not create a second gallery table for images.
- V018 reaction PK `(catalog_item_id,user_id,kind)`, user-kind-created index,
  ACTIVE comment feed index and author-created index are reusable.
- V019 links SOCIAL_COMMENT to moderation cases with target constraints.
- Adding catalog video later requires a new additive migration for media-purpose/
  IMAGE-only constraints; the purpose enum alone is insufficient.
- No indexes or migration were added during G0. Next migration number must be
  checked again immediately before G2/G5 work.

## Security and query observations

- `MerchantAccessPolicy` checks persisted active membership and capabilities;
  MANAGE_CATALOG_STRUCTURE is the existing item-edit capability. Do not grant it
  to STAFF or to Admin by assuming their system role implies merchant access.
- `AdminAccessPolicy.requireAdmin` is the established read guard. New Admin reads
  must invoke it and return private/no-store; hiding the page alone is insufficient.
- Existing social public predicates require item ACTIVE, no deletion, approved/
  not-required moderation, and active visible merchant. Reuse exact conditions.
- `CatalogEditService.updateItem` currently updates name/description/media without
  a moderation-policy collaborator. Before caption exposure, G2 must explicitly
  integrate approved edit revalidation. This is source evidence of an integration
  gap for new content, not a claimed live exploit or a speculative repair in G0.
- Current media completion checks HEAD/type/size and magic prefixes. Video support
  is restricted to AD_BANNER; maxVideoBytes is 50 MiB. Reliable duration/codec probe
  and protected moderation-media viewing require design before video activation.
- Summary batching and lazy comments already exist. Preserve Catalog-mode request
  behavior and avoid per-card detail/media queries when adding preview.
- Actual populated query plans, payload/load/bundle/network measurements for V2
  are NOT RUN: its endpoints do not exist. Do not label inferred query costs PASS.
