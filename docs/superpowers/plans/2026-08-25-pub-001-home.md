# PUB-001 Home Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/` as the Figma-faithful PUB-001 public buyer Home without changing backend contracts or treating other routes as visually complete.

**Architecture:** Keep `app/page.tsx` as a thin route and add a client-owned Home screen that reuses browse-location state and generated API types. Add only the shared primitives required by PUB-001, use scoped CSS Modules for Home/layout styling, and retain global CSS for semantic tokens and the Inter font. Fetch three independently recoverable discovery sections so one failed section does not blank the whole page.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, CSS Modules/global CSS, generated `@covie/api-client`, Vitest/Testing Library, Playwright.

**Figma source:** [PUB-001 production board](https://www.figma.com/design/4LcMXFQz3BnU1EXzBk69t2/CoVie-%E2%80%94-V1-UI-Design?node-id=279-2), default `282:290`, responsive `282:388`, missing-location `282:542`.

**Known contract limitation:** `CatalogItemSummaryResponse` currently exposes media, name, merchant, resolved location, price, item type and listing kind, but not rating, fulfillment badge/fee, or cart count. PUB-001 must not invent these values; record the resulting visual deviation instead of expanding backend scope in this slice.
