# Ad Engine Implementation Plan

> **For agentic workers:** Use subagents for implementation and independent review. Steps use checkbox syntax for tracking.

**Goal:** Deliver the user-approved image/video/CSS ad engine, administration, merchant submission and approval, and view/click analytics.

**Architecture:** Spring Boot owns campaign validation, media ownership, merchant authorization, approval, schedules and metrics. Generated OpenAPI types drive a shared React AdSlot and management screens. Slots occupy available space without shrinking or covering catalog content.

**Tech Stack:** Spring Boot, PostgreSQL/Flyway, existing S3 media pipeline, Next.js/React, CSS modules, Vitest, JUnit and Playwright.

## Approved scope

- Image WebP/JPEG/PNG, video MP4/WebM and flash/nearby/spotlight/hero CSS creatives.
- Admin campaign CRUD, schedule, device, placement, priority, manual activation and approval/rejection.
- Merchant campaign CRUD/submission for their own store/items; content updates invalidate approval.
- SIDEBAR_LEFT on home/search only when viewport >=1440 and actual gutter fits. HOME_HERO/IN_FEED mobile-friendly home/search slots; ITEM_DETAIL below primary detail. No ads on merchant profile, checkout, cart, account, orders or management pages.
- Rotation pause/previous/next, reduced-motion support, muted video with controls, explicit ad label.
- View after >=1 continuous second of actual visibility, non-blocking click, deduplicated events, daily clicks/impressions/CTR and auto-refresh chart.
- No payments, bidding, deployment or changes to recovered runtime data.
